## 2025-05-21 - Single-pass Zero-Allocation G-code Parser Optimization
**Learning:** Libc string functions like `isspace`, `toupper`, `strchr`, `strtof`, and `atoi` introduce significant overhead due to locale handling, multiple memory passes, and heap/stack string allocations. In embedded real-time G-code processing systems like ESP32 firmware, replacing multi-pass string formatting with a single-pass zero-allocation scanner using fast inline ASCII conversion and fast custom float/int parsers yields ~10.6x throughput improvements (~0.18s vs ~1.92s for 6M parses).
**Action:** Always prefer zero-allocation single-pass string parsing using direct ASCII checks (`to_ascii_upper`, `is_ascii_space`) and fast numeric conversion routines (`fast_atof`, `fast_atoi`) when parsing high-frequency text streams on microcontrollers.
