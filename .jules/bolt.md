## 2025-08-09 - [Bug-compatible G-code Parser Optimization]
**Learning:** In legacy systems (like G-code parsers), performance optimization via rewriting loops into single-pass scanners must carefully preserve existing "buggy" or "quirky" parsing behaviors (such as treating trailing parameter keys without numbers like "G1 X" as valid with 0.0 value). Additionally, manual pointer increments inside multi-branch parameter loops can lead to critical memory safety bugs (buffer overreads) if pointer bounds are not strictly validated at every potential termination.
**Action:** Always write a parallel verification test suite covering both positive, negative, and malformed boundary cases before submitting any optimization changes. Check that every pointer increment inside nested parsing loops is preceded by a boundary check or handles the null terminator safely.
